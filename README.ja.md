# Macモニター

**CPU・GPUの負荷、メモリの使用状況とプレッシャー、内蔵SSDの容量、外付けSSDの容量とSMARTの状態**を確認するmacOS用メニューバーアプリです。各項目の代表値をメニューバーに表示し、クリックすると4枚のカードで内訳と最近の推移を確認できます。

表示言語は日本語／英語に対応し、メニューバーに出す数値・項目の非表示・自動更新の間隔を設定できます。Appleシリコン搭載Mac、macOS 14以降が対象です。外付けSSDはモデルを限定せず、接続中の候補から設定で選びます。容量はSMARTなしでも取得し、温度・健康情報はSSD・ケース・診断ツールの対応状況に応じて表示します。CPU・GPU・メモリ・内蔵容量は外付けSSDがなくても監視します。

[English](README.md)

## 使い始める

### ダウンロードとインストール

1. [Releases](https://github.com/dataarthub/mac-monitor/releases) から `MacMonitor.zip` をダウンロードします。
2. 解凍して現れた `MacMonitor.app` を `/Applications`（アプリケーションフォルダ）へドラッグ＆ドロップします。

> [!NOTE]
> **macOS Gatekeeper（未署名アプリの警告）への対処**
> 本オープンソース版は Apple Developer ID 証明書による公証ではなくアドホック署名（`codesign --sign -`）を行っているため、初回起動時に「開発元を検証できないため開けません」「悪質なソフトウェアかどうかを検証できないため開けません」と表示される場合があります。
> - **方法1（Finder）**: `MacMonitor.app` を **右クリック（または Control + クリック）して「開く」を選択** し、確認ダイアログで「開く」をクリックします。
> - **方法2（システム設定）**: **システム設定** > **プライバシーとセキュリティ** を開き、セキュリティ欄に表示される「このまま開く」をクリックします。
> - **方法3（ターミナル）**: 以下のコマンドで隔離属性（Quarantine）を解除します。
>   ```sh
>   xattr -cr /Applications/MacMonitor.app
>   ```

### 起動と操作

`MacMonitor.app` をダブルクリックして起動します。メニューバーの表示をクリックすると詳細を開閉できます。詳細右上の歯車から設定を開き、設定右上の「閉じる」で戻ります。アプリを終了するには詳細下部の「終了」を使います。

| 項目 | 詳細に表示する情報 |
|---|---|
| CPU・GPU | CPU使用率、ユーザー／システム／空きの内訳、CPUモデル・コア構成、負荷平均（1／5／15分）、GPU全体・描画・タイル使用率、CPU／GPUそれぞれの推移 |
| メモリ | macOSのメモリプレッシャー、使用量／総容量・使用率、アプリ用・固定・圧縮・キャッシュ目安・スワップ、使用率の推移 |
| 内蔵SSD | 総容量・使用容量の概算・使用率、実際の空き、削除可能領域込みの利用可能容量、削除可能容量の目安、ファイルシステム・ボリューム名、起動時からの空き増減と推移 |
| 外付けSSD | 使用容量／総容量・残量・使用率・対象ボリューム、現在温度・起動後の最高温度、累積読み書き量、寿命使用率の目安、予備領域、稼働時間、異常終了、メディアエラー・重大警告、SMARTの状態、更新時刻 |

メニューバーのアイコンと数値は監視状態に応じて緑・オレンジ・赤、取得不能時はグレーになります。詳細の参考値の青は警戒度を表しません。メニューバーにマウスを重ねると項目名と警告、詳細の各行に重ねると説明が読めます。

## 設定

変更はすぐに反映され、アプリ専用の `UserDefaults` に保存して次回起動時に引き継ぎます。

### 表示言語と代表値

言語は「自動（macOSに合わせる）／日本語／English」から選びます。自動はmacOSの最優先言語が日本語なら日本語、それ以外なら英語です。このアプリのラベル・説明・ツールチップ・警告・エラーに適用します。

「各欄に表示する数値」で代表値を選びます。同じ値をメニューバーと対応する詳細カードの先頭に表示します。

| 項目 | 選べる代表値 | 初期値 |
|---|---|---|
| CPU・GPU | CPU使用率、CPU負荷平均（1分）、GPU全体・描画・タイル使用率 | CPU使用率 |
| メモリ | 使用率、使用量、メモリプレッシャー、圧縮メモリ、スワップ使用量 | 使用率 |
| 内蔵SSD | 実際の空き、削除可能領域込みの利用可能容量、削除可能容量の目安、使用容量（概算） | 実際の空き |
| 外付けSSD | 温度、累積書き込み・読み取り、寿命使用率の目安、累積稼働時間、容量の使用率・残量・使用容量 | 温度 |

各欄には「メニューバーに表示しない」もあります。非表示にしても詳細の代表値を保持し、監視と警告は全項目で継続します。全欄を非表示にしても、詳細を開くためのアプリアイコンは残ります。取得できない代表値は「—」です。

メニューバーの数値は各アイコンのすぐ右に左寄せし、確保した余白は数値の後ろに置きます。メニューバーは余白を抑え、使用率は3桁、温度は2桁、プレッシャーは翻訳後の状態名に必要な幅を確保します。それ以外は実際の表示に必要な幅を使います。より桁数の多い値が現れたときだけ必要な分を広げ、起動中はその幅を保持して伸縮の繰り返しを防ぎます。警告アイコンは警告があるときだけ場所を使います。代表値・言語・表示する項目を変更したときも幅が変わる場合があります。

代表値を変えても警告の基準とグラフの対象は変わりません。グラフはCPU／GPUの全体使用率、メモリ使用率、内蔵SSDの実際の空き、外付けSSDの温度を表示します。

### 監視する外付けSSD

設定の「監視する外付けSSD」で選択します。macOSがSSDと報告する外付け物理ドライブに加え、USBケースが種別を公開しないものも「SSD種別不明」として候補に含めます。HDDと明示されたもの、内蔵ドライブ、ディスクイメージは除外します。候補にはデバイス名・物理容量・現在のディスク番号を表示します。「再検出」ですぐに一覧を更新でき、通常の外付け更新時にも検出し直します。

初回は一覧の先頭を選び、以後はパーティション／ボリュームのUUIDで選択を保存します。ボリューム名や `diskN` が変わっても同じ対象を追跡します。取り外した対象は未接続として残し、現在値を消去して別のドライブへ勝手に切り替えません。再接続するか、別の対象を明示的に選んでください。再フォーマットでUUIDが変わると再選択が必要です。UUIDがない媒体は現在の起動セッション限定のIOKit識別情報を使うため、再起動後は再選択が必要になる場合があります。同じ識別情報が複数ある場合は、誤選択を避けるため取得しません。

対象を変えると前の値・起動後の最高温度・温度グラフを消し、切り替え前に始まった読み取り結果も破棄します。代表値の設定は保持します。選んだ値を取得できず、容量が取得できる場合はメニューバーとカードを一時的に「残量」表示にし、カードに理由を添えます。取得可能になれば元の代表値へ戻ります。

### 自動更新の間隔と画面配置

| 対象 | 選べる間隔 | 初期値 |
|---|---|---|
| CPU・GPU・メモリ・内蔵容量 | 1／2／5／10／30秒 | 2秒 |
| 外付け容量・SMART | 5／15／30／60秒 | 15秒 |

間隔を変えると該当するタイマーを設定し直し、その対象のグラフ履歴をリセットします。履歴はメモリ上の最大60点で、初期設定ではシステム情報が直近約2分、外付け温度が直近約15分です。履歴は終了時に消え、増え続けるログは作りません。内蔵SSDの空き増減の基準は起動時の値を保持します。「今すぐ更新」はタイマーにかかわらず読み取りを要求します。更新を遅くすると警告の検知・回復の反映も遅くなります。

詳細画面は幅680ポイントで、カードを左右の余白まで広げます。カードや文字を縮小せず、内容に合わせてウインドウを縦に伸ばし、Dockとメニューバーを除く画面内に収めます。ヘッダー・状態欄・フッターは固定し、カードはスクロールしません。状態欄は正常時の緑、警告時のオレンジ／赤、情報未取得時のグレーで同じ高さを使います。

## 色と警告の基準

| 項目 | 緑 | オレンジ | 赤 |
|---|---|---|---|
| CPU使用率 | 70%未満 | 70%以上90%未満 | 90%以上 |
| メモリプレッシャー | macOSのnormal | macOSのwarning | macOSのcritical |
| 内蔵SSDの実際の空き | 20 GB以上 | 10 GB以上20 GB未満 | 10 GB未満 |
| 外付けSSD温度 | 65℃未満 | 65℃以上70℃未満 | 70℃以上 |

CPUの色は負荷を示し、警告アイコンは90%以上が30秒続いてから出します。メモリプレッシャー、内蔵容量不足、外付け温度上昇、SMARTの問題でもメニューバーの警告アイコンと詳細のメッセージを表示し、回復すると解除します。GPU使用率・負荷平均・外付けの容量使用率には独自の警告しきい値を設けていません。

メモリの色は、代表値にかかわらず**macOSのメモリプレッシャー**を使います。使用率やスワップ容量だけのしきい値ではありません。例えば使用率90%でもOS判定がnormalなら警告は出ず、50%でもwarningなら注意になります。`kern.memorystatus_vm_pressure_level` の3段階を表示するため、アクティビティモニタの連続的なグラフとは表示範囲が異なります。macOSは空きメモリ、スワップの頻度、固定メモリ、キャッシュなどを考慮します。[Appleのメモリプレッシャーの説明](https://support.apple.com/ja-jp/guide/activity-monitor/actmntr1004/mac)

SMARTの重大警告・メディアエラーが0以外の場合、またはSMART正常判定に失敗した場合は、温度とは別に赤で強調します。温度・容量のしきい値は早めに気づくための目安で、メーカー別の故障判定ではありません。CPU高負荷や過去の異常終了回数だけでも故障とは判定しません。

## 詳細の読み方

### CPU・GPU・メモリ

CPU使用率は前回取得からのMachのCPU時間の差分を使い、全論理コアを合わせた0〜100%で表示します。ユーザーにはniceを含み、ユーザー＋システムが全体使用率です。1コアだけ高負荷でも全体は低く見える場合があります。構成は `sysctl`、負荷平均は `getloadavg` から取得します。負荷平均は実行中／実行可能な仕事の数の平均で、%ではなくコア数と比べる参考値です。コア別メーターは詳細には出さず、診断出力にコア別の値を残しています。

GPUはIOKitの `IOAccelerator` の `PerformanceStatistics` を読みます。全体・描画・タイルは処理段階が違うため、互いに加算しません。統計の公開状況はMacやドライバで異なり、取得不能時は「—」です。複数GPUの統計が取れる場合は最も使用率が高いGPUとその内訳を表示します。このMacのApple M4で全体・描画・タイルの値を取得確認しました。

メモリのアプリ用は匿名メモリから削除可能メモリを除いた概算、固定はRAMに保持する必要がある容量、圧縮は圧縮データがRAM上で使う容量です。キャッシュ目安はファイル関連メモリ＋削除可能メモリで、使用量の内訳とは別に表示します。スワップは起動ディスク上の使用量です。各値は状況を理解する参考値で、警告原因の特定やアクティビティモニタとの完全一致を意味しません。メモリの単位は1024³バイトをGB表記します。

### 内蔵SSDの容量

`/System/Volumes/Data` からファイルシステムの容量を取得します。使用容量の概算は総容量－実際の空き、使用率は使用容量／総容量です。APFSでは同じコンテナのボリュームで容量を共有するため、スナップショットや他ボリュームも含み、Data内のファイルサイズ合計ではありません。ファイルシステム形式・ボリューム名も同じ領域から取得します。ストレージの容量は10⁹バイトを1 GBとします。

「利用可能容量」はmacOSの `volumeAvailableCapacityForImportantUsage` が返す、必要時に自動削除できる領域を考慮した見積もりです。「削除可能容量の目安」は利用可能－実際の空きを0以上にした値です。Time Machineのローカルスナップショットやキャッシュなどを含む場合がありますが、Time Machine単独や全スナップショットの合計ではなく、Finderとも異なる場合があります。設定したシステム更新間隔で読み取り、警告と推移には実際の空きを使います。アプリから削除処理は行いません。

参考：[Appleの容量API](https://developer.apple.com/documentation/foundation/urlresourcevalues/volumeavailablecapacityforimportantusage)、[Time Machineのローカルスナップショット](https://support.apple.com/ja-jp/102154)。

### 外付けSSDの容量とSMART

容量はSMARTから独立して `diskutil` とファイルシステムAPIで取得します。選択した物理ディスクに属するマウント済み領域を対応付け、同じAPFSコンテナは二重に数えません。未マウント領域や、複数の物理ディスクにまたがって単体への帰属ができないAPFSコンテナは容量集計の対象外です。対象ボリューム名、使用率・実際の残量・使用容量／総容量を表示します。使用容量はスナップショットなどを含む総容量－空きの概算です。接続されていても未マウントなら容量は「—」となり、SMARTだけ取得できる場合があります。

SMARTは `smartctl --scan -j` の候補をIOKitやデバイスパスで選択した物理ディスクへ対応付け、報告されたデバイス種別で読みます。NVMeに固定せず、スキャンに出ない場合はその物理デバイスへの自動検出を試します。モデル名のフィルターは設けず、選択したドライブだけを読み取ります。NVMeでは下表の詳細を、SATAなどでは対応する共通JSONの温度・SMART判定・稼働時間・予備領域・耐久性消費率を読みます。[smartctlの共通ATA JSON項目](https://www.smartmontools.org/static/doxygen/ataprint_8cpp_source.html)に従い、メーカー依存のATA生カウンターを推測したりNVMe単位で換算したりせず、未対応の値は「—」です。

smartctlがない、USB経由の診断情報に非対応、権限の制限、読み取り失敗の場合も、マウント済み領域の容量表示は継続します。カードに制限の説明を出し、取れない温度・健康状態を0・正常・故障として扱いません。明示的なSMART異常や重大警告・メディアエラーは温度がなくても警告します。温度が取れない期間やドライブ変更時には温度グラフをクリアします。設定した外付け更新間隔で容量とSMARTを再取得し、SMARTが復帰すれば代表値も戻ります。

| SMARTの項目 | 意味 |
|---|---|
| 現在温度／起動後の最高温度 | NVMeの現在温度と、アプリ起動後に観測した最高値 |
| 累積読み取り／書き込み | `data_units_read`／`data_units_written` を1単位512,000バイト、1 TB＝10¹²バイトで換算したホスト転送量。物理的なNANDへの転送量やメーカー公称TBWとは別 |
| 寿命使用率の目安 | `percentage_used` によるメーカー推定の耐久性消費割合。0%は1%未満の消費を含み、100%超も表示。容量の使用率や残り寿命の保証ではない |
| 予備領域／しきい値 | 不良ブロック置換などに使う予備領域とSSDが報告するしきい値。ファイル用の空き容量とは別 |
| 累積稼働時間 | `power_on_hours`。アプリ起動後ではなくSSDの累積時間 |
| 異常終了の累積 | 正常な終了通知なしに電源を失った回数。過去の累積だけで現在の故障とは判定しない |
| メディアエラー／重大警告 | メディア・データ整合性エラーの累積とCritical Warningのビット値（16進数） |

追加の取得不能・不正な値は「—」です。累積カウンターはSSDが保持しているため、転送履歴を保存したり追加ポーリングしたりする必要はありません。[smartmontoolsのNVMe出力実装](https://www.smartmontools.org/static/doxygen/nvmeprint_8cpp_source.html)

## 外付けSSDの依存ツールと接続条件

SMARTの温度・健康情報を取得する場合は、別途 [`smartmontools`](https://formulae.brew.sh/formula/smartmontools) が必要です。

```sh
brew install smartmontools
```

`smartctl` はアプリに同梱しません。`/opt/homebrew` と `/usr/local` の `bin`／`sbin` を探します。容量の取得には不要です。接続方式ごとの診断対応は次のように確認できます。

1. `smartctl --scan -j` で対象の物理ドライブを探す。
2. `smartctl -a -j -d <スキャンのtype> "<スキャンのデバイス名>"` を実行する。スキャンに出ない場合は、現在の物理ディスク番号で `smartctl -a -j /dev/diskN` を試す。
3. JSONに実際に含まれる共通の温度・SMART項目を確認する。モデル名を変更するためのソース修正は不要。

ファイルを読み書きできてもSMARTを読めないUSBケースがあります。「USB-C」「USB4」「NVMe」の表記だけでは診断情報の取得可否を判断できません。ケース・ドライバ・macOSの診断バックエンド・smartctlのデバイス種別の対応が必要で、パーサーの変更だけでは解決できない場合があります。その場合は容量の監視を使い、健康情報は不明のまま表示します。[smartctlのmacOS実装](https://github.com/smartmontools/smartmontools/blob/master/smartmontools/os_darwin.cpp)、[公式マニュアル](https://github.com/smartmontools/smartmontools/blob/master/smartmontools/smartctl.8.in)

2026年10月3日のハードウェア動作確認は、Appleシリコン搭載Mac mini、macOS 26.3、Crucial T500 2TB（`CT2000T500SSD8`）、ロジテック LGB-PNVU4C、NVMeとして認識されるUSB4接続、smartmontools 7.5で行いました。他の組み合わせは未検証です。

他モデルのNVMe・共通SATA項目の解析、ツールなし／SMART非対応時の容量表示、複数ドライブの選択、切断・再接続、遅い読み取り結果の破棄はテストデータで検証しています。このMacでは実機T500の容量・SMARTに加え、smartctlを使えない条件での実際の容量表示も確認しました。他のSSD・ケースの実機組み合わせは未検証です。温度しきい値はアプリ共通の目安なので、選んだSSDの動作条件も参照してください。アプリやプロジェクトを別ドライブへ移しても保存した監視対象は変わりません。

## ビルドと診断

Appleシリコン搭載Mac、macOS 14以降、XcodeまたはCommand Line Toolsが必要です。現在は `arm64` 向けで、Intel向けビルドは未検証です。

```sh
bash build.sh
```

`MacMonitor.app` を作成し、アドホック署名と自動確認を行います。中間ファイルとモジュールキャッシュはプロジェクト内の `.build` に置きます。

```sh
# 現在のメトリクスを1回読み取る
'MacMonitor.app/Contents/MacOS/MacMonitor' --check
# 回帰チェック
'MacMonitor.app/Contents/MacOS/MacMonitor' --self-test
# 別のsmartctl実行ファイルを使う
'MacMonitor.app/Contents/MacOS/MacMonitor' --smartctl /absolute/path/to/smartctl
```

109項目のチェックは、メトリクスと警告、プレッシャーと使用率の違い、GPUの欠測・不正値、容量の概算、SMART換算、言語・設定保存・更新間隔、外付けの対応付け、画面内への配置、メニューバーの余白を抑えること・桁数増加後の幅保持・警告時だけのアイコン領域を検証します。選択対象の識別・保存、NVMe／共通SATA項目、SMART非対応時の容量表示、識別情報の重複、切断・再接続、古い結果の破棄も対象です。`--check` は取得可能なCPU内訳・コア別・負荷平均、GPU、メモリ、内蔵容量、外付け容量・対象名、SMART情報を出力します。

`--smartctl` は実行ファイルの指定で、ドライブの指定ではありません。`--check` は保存したドライブ選択（未選択なら先頭の候補）に従い、候補一覧と容量のみ表示する理由も出力します。取得不能な健康情報を補完しません。制限された実行環境ではSMART・スワップ・メモリプレッシャーを読めない場合があるため、通常起動やターミナルでも確認してください。アプリから管理者権限は要求しません。
